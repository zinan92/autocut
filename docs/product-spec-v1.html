Transcript-first 视频剪辑系统 v1 提案

Transcript-first workbench  |  工作区 autocut  |  基于现有 architecture.md
这不是"自动剪辑软件",而是一个 Agent 编排的视频制作系统。
主语是剪辑底座:你给 1–3 段口播视频 → 系统转写 → 你改文字顺序就改了视频顺序 → 生成 EDL → 剪成 clean master。
Remotion overlay 是签名最终层 —— 架构上最后做,但它是这个项目存在的理由(人在前景 + 透明动画层),是它跟任何剪辑工具的本质区别。

功能模块 · 现状 vs 缺口 + Success Criteria

01Ingest
已有 ✅
确定性脚本 · ingest-video.mjs
读源视频:横竖屏 / 时长 / fps / codec / 音轨 / HDR;多段一致性检查。
Success Criteria
  • 100% 识别横竖屏 → 源竖屏则成片默认竖屏
  • 多段尺寸/fps 不一致时明确报警
  • 已验证:识别现有视频为 720×1280 vertical
02Transcribe
部分 ⚠️
外部 ASR / 缓存 · transcribe-video.mjs
生成 word-level 带时间戳文字稿。现状只支持"复用已有 transcript",没接真 ASR —— transcript-first 产品里这是承重墙。见 决策 #2。
Success Criteria
  • 每词有 start/end;同源不重复转写
  • 支持从文字映射回视频时间段
  • ASR 不可用时明确失败,不假装成功
03Transcript Assembly ★ 核心交互
缺失 ❌
AI + 人工 · 全新模块(当前无脚本)
把多段视频转成 assembly.md,每个文字 block 保留 source/start/end。你只改 block 顺序或删 block,视频顺序就变了。例:P1 → P2前80% → P3 → P2后20%。见 决策 #1。
Success Criteria
  • 用户不用手填秒数;"80%"只是语义附近
  • 切点 snap 到句子/停顿/词边界,不切词中间
  • 改顺序后能稳定生成 multi-source EDL
  • 无法映射时明确标记(不静默出错)
04Multi-source EDL
部分 ⚠️
确定性协议层 · build-edl.mjs
关键帧/keep+delete ranges。现状是单源 autocut,Park 的需求要升级成多源 manual EDL(跨 P1/P2/P3 拼接重排)。含口播清理:删长静音/语气词/卡顿/重复,删前保后。
Success Criteria
  • 默认不激进删除;删>15% 或语义删除必须 review
  • 每个接缝 30ms audio fade,避免爆音
  • 接回多源后统一分辨率/fps/音频格式
05Clean Master
已有 ✅
确定性脚本 · render-edl.mjs (ffmpeg)
按 EDL 剪出干净成片 —— 这是 overlay 之前的"可靠剪辑底座"。
Success Criteria
  • 无删除片段时能正确直出 cut mp4(已验证)
  • 多源拼接接缝无跳音/跳帧
06Remotion Overlay ♥ 签名层
已有 ✅
Remotion 视觉合成 + Storyboard · V8 最佳
这是项目的差异化与存在理由:人在前景,透明动画层漂浮其前(技能表/大数字/图表卡/双语字幕/房间感)。架构上最后做,但它定义产品。

  • 字幕在 overlay 之后叠;不遮人脸
  • QA 几何 = 100;每个项目可选要不要 overlay

需要 Park 拍板的 2 个决策(决定产品难度)

决策 #1 · Assembly 模式:只重排,还是允许改写?

这是核心交互的可行性分水岭。Codex 在 session 里已点出:能不能稳定把文字映射回视频,取决于这个。
A. 只重排 / 删除 block ✓ Park 已选

用户只移动或删除文字段落,不改字。每段保留 source+时间戳,映射回视频完全确定。

成本低 · 确定性高 · 现有能力即可扩
B. 允许改写文字

用户能改写文案。改写后的文字无法直接定位原视频,需要 fuzzy matching,确定性下降,工程量大增。

成本高 · 确定性低 · 改写文字只能当字幕用

决策 #2 · ASR 入口:转写从哪来?

transcript-first 产品里转写是承重墙,现状"只复用已有 transcript"撑不起。
A. MLX Whisper 本地 ✓ Park 已选

本机跑,无需 API key、不上传、可批处理,符合自动化口播流。

无外部依赖 · 隐私好 · 需装一次本地后端
B. 云端 ASR / 维持复用

云端要 key+联网+成本;维持"只复用"则每次得先有现成 transcript,不够自动。

云端=钱+key · 复用=不够自动
不阻塞的开放项:是否允许"纯剪辑、完全不加 overlay"的项目(纯口播成片)。建议先不定死,等做起来自然落地 —— overlay 已设计成 per-project 可选。
现状一句话:8 个模块里 5 个已有、2 个部分、1 个(★Assembly)缺失。重设计 = 把"改文字→改视频"的 Assembly 立为一等模块 + 把单源 autocut 升级成多源 EDL。
还差:此工作区尚未 git 化、未 push GitHub。
